# 微信图片与文件入站

微信连接接收图片和文件消息，包括没有文字的附件消息，以及引用消息中的附件。
图片以 `localImage` 输入交给现有会话，文件通过提示中的本地路径提供。
本功能只接收附件，不注册附件发送工具，也不改变会话、模型或项目配置。

## 接收与校验

- 支持图片项（类型 2）、文件项（类型 4）及最多 4 层引用。
- 每条消息最多处理 10 个附件，解密后的附件总量最多 100 MiB。
- 加密媒体使用 AES-128-ECB / PKCS7，兼容原始密钥与十六进制密钥的 Base64 表示。
- 图片可使用官方 CDN 的明文地址。文件必须提供加密密钥；提供长度或 MD5 时验证其与明文一致。
- 下载客户端独立于消息客户端，不携带机器人认证、路由头或 Cookie，不跟随重定向。
  生产下载地址仅接受官方 CDN 的 HTTPS 地址；回环测试地址只在单元测试中配置。
- 个别附件失败时，成功附件和原正文仍可处理，回复中提示失败原因。
  只有附件且全部失败时返回接收失败，不发起空会话回合。

## 本地收件目录

附件保存在所选工作目录的 `.codex-plus/weixin/inbox/<随机标识>/` 下。
远端文件名被限制为单个安全组件，并添加随机前缀，避免路径穿越和同名覆盖。
先写临时文件、同步内容，再原子发布最终名称；成功登记归属后才提供给会话。

每次创建收件目录时，检查已归属的历史收件目录：超过 7 天或超出 100 个保留目标的目录可被清理。
清理只处理本功能生成、清单有效、文件名/大小/修改时间与清单一致的目录；
使用中的目录通过独占文件锁保护，修改过的附件、未知文件、嵌套目录、损坏清单及链接内容均保留。
只逐个删除已登记文件并移除空目录，不递归清除用户内容。因此受保护内容可能使实际目录数超过保留目标。
锁由操作系统随进程退出释放；中断留下的未知临时文件按未知内容保留。

账号中的 `@`、`.` 和大写字符沿用既有状态文件名规则，不转换大小写、不迁移旧状态文件。

## 验证边界

普通 Rust 单元测试覆盖解密向量、回环下载、长度/校验和/大小限制、路径和归属保护、输入 JSON 及账号状态回读。
这些测试不替代真实微信图片/文件传输及实际会话读取验证。不同客户端版本和媒体类型仍需分别记录验收结果。
