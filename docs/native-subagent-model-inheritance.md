# 原生子智能体的模型身份继承

Codex 经网关创建的原生子智能体，继承直接父回合的逻辑模型身份。身份包括供应商前缀、模型名以及聚合模型标识，例如：

- 父回合使用 `supplier-a/gpt-6.1-sol` 时，子智能体继续使用该完整模型标识。
- 父回合使用 `group/research` 时，子智能体继续使用该组；组内的手动选择、轮换和失败切换仍由网关正常处理。
- 子智能体显式发送其他裸模型名，也不会因此进入整个供应商池重新选择供应商。

聚合组本身就是有效模型身份。继承时不会将它替换成某次请求实际选中的供应商或上游模型。

网关通过原生请求中的线程和回合元数据识别直接父回合，将逻辑模型按 Codex Home、SQLite Home、线程及回合持久化。管理器重启、切换全局默认模型或并发处理其他会话，不会改变已记录回合的身份。

父回合尚未记录时，只从当前 Codex Home 内、原生线程数据库指向的 rollout 中读取对应 `turn_context`；不使用当前全局默认供应商或线程的最新模型代替指定父回合。父回合自身也是子智能体且没有继承记录时，拒绝根据其原始裸模型推断供应商。

缺少必要父回合标识、父回合无法核实、身份冲突或已继承模型不再可路由时，请求明确失败，不静默切换供应商。普通 API 请求及其他 Agent 的网关行为保持原有规则。单独配置的 Codex 起名和自动审批模型也沿用原有规则。

原生 `spawn_agent` 工具描述会提示省略 `model` 参数，让客户端在创建阶段继承完整身份；网关在请求阶段继续校验实际身份。该策略不会修改原生会话数据库或历史用量。
